# 反风控实战记录

> 这份文档记录的是**真实触发过风控之后的复盘**，不是理论。
> 核心结论一句话：**自动化投递最大的风险不是「投得慢」，而是「投失败了还在继续跑」。**
>
> 最后更新：2026-10-02（猎聘风控事件当晚）

---

## 1. 四个平台的风控强度（实测）

| 平台 | 反自动化机制 | 实测强度 | 单日安全量参考 |
|---|---|---|---|
| **BOSS直聘** | 唯一有主动反自动化机制的平台；有开源作者明确警告「不要依赖程序批量投递」 | 🟡 中 | 30–50（硬上限约 100 沟通/天） |
| **智联招聘** | 部分组件拒绝合成事件（级联选择器），但没有主动风控 | 🟢 低 | 30–50 |
| **前程无忧** | 同上，组件层面的限制为主 | 🟢 低 | 30–50 |
| **猎聘** | **有主动风控，且触发阈值最低** | 🔴 极高 | **3–10** |

> ⚠️ **别把「页面能点」当成「平台不管你」。**
> 智联/前程无忧 的难点在技术（组件不响应合成事件），猎聘/BOSS 的难点在风控。
> 两类问题要分开对待。

## 2. 完整案例：猎聘风控事件复盘

### 2.1 时间线

| 时间 | 事件 |
|---|---|
| 22:34 | 开始批量投递猎聘（广州 Java） |
| 22:34–22:38 | 脚本报告「✅ 已点击投递」× 4，**实际一个都没投出去**（详见 2.3） |
| 22:38 | 第 5 个岗位的页面上出现风控提示：「账号行为异常，请进行短信验证」 |
| 22:40 | 立即停止猎聘所有自动化 |
| 23:10 | 用户手动完成短信验证，风控解除 |
| 23:15 | 修正按钮点击后重投，**3/3 成功，未再触发风控** |

### 2.2 现象

第 5 个岗位的详情页上，整页被替换成：

```
企业招聘套餐咨询   退出
账号行为异常
尊敬的客户您好，猎聘安全中心发现您的账号存在异常访问行为，
为了保障您的账号安全，请进行短信验证，感谢您对猎聘的理解和支持。
当前账号 1XX****XXXX   获取验证码   验证   退出
```

**注意：这是整页替换，不是弹窗。** 脚本如果不检查页面内容，会把后续所有操作都当成「页面结构变了」而静默失败。

### 2.3 当时犯的错：把「点击成功」当成「投递成功」

猎聘的投递弹窗里，**文字为「立即投递」的元素有三个**：

```html
<div class="ant-c-modal-footer">                          <!-- ① 外层容器 -->
  <button class="ant-c-btn ant-c-btn-primary">            <!-- ② 真正的按钮 ✅ -->
    <span>立即投递</span>                                  <!-- ③ 内层文字 -->
  </button>
</div>
```

脚本用的是「按文字找第一个匹配」：

```js
// ❌ 按文档顺序取第一个 → 取到 ① 那个 DIV，点击无效、而且不报错
Array.from(document.querySelectorAll('button, a, span, div'))
  .find(e => e.innerText.trim() === '立即投递')
```

结果：**4 次「投递」全部静默失败**，但脚本每一步都打印「✅ 已点击投递」。

事后的证据很明确 —— 重开这些岗位的详情页，「投简历」按钮**原封不动地还在**。

> **教训 1：`el.click()` 不抛异常 ≠ 业务动作生效。**
> 合成点击对没有事件处理器的元素是完全无副作用的静默操作。

### 2.4 真正的风控诱因

一开始我以为「是投得太快」。复盘后不是：

```
投递失败（没有任何网络请求）
   ↓
脚本继续跑下一个岗位
   ↓
再打开一次职位详情页（真实的页面加载 + 接口请求）
   ↓
4 次失败 = 连续加载 4 个详情页，却没有任何一次「投递」动作
   ↓
在平台看来：一个账号在短时间内高频浏览职位、但从不投递
   ↓
判定「异常访问行为」
```

**关键点：真正的风控信号是「页面加载次数」，不是「点击次数」。**
点击失败不产生流量，但脚本为了下一个岗位又去加载了新的详情页 —— 流量照常产生。

修正按钮点击后，同样连投 3 个（**每次都真正产生投递请求**），反而没触发风控。

> **教训 2：失败的循环比成功的循环更危险。**
> 成功时每个岗位产生「1 次浏览 + 1 次投递」，比例是健康的；
> 失败时变成「N 次浏览 + 0 次投递」，这才是异常行为特征。

### 2.5 处置

1. **立刻停手** —— 不重试、不换脚本、不再加载任何猎聘页面
2. **告知用户** —— 短信验证必须本人做，这是刻意保留的边界
3. **修 bug，而不是降速** —— 根因是点击没生效，降速只是掩盖问题
4. **恢复后小批量验证** —— 先投 3 个确认通畅，再考虑放量

> **教训 3：遇到风控先查「我的动作到底生效了没有」，再考虑「是不是太快了」。**
> 很多时候风控是结果，不是原因。

## 3. 判断信号表：出现任何一个就立刻停

| 信号 | 含义 | 动作 |
|---|---|---|
| 整页出现「账号行为异常」「短信验证」 | **风控已触发** | 立刻停止该平台，交用户本人验证 |
| 出现验证码 / 滑块 | 风控触发 | 停止，人工处理，当天别再操作 |
| 要求重新登录 | 会话被踢 | 停止，人工登录，当天别再操作 |
| 连续多个操作「点击成功但无效果」 | 可能是页面结构变了，或已被限制 | **停下诊断**，不要继续跑 |
| 页面结构突然大面积不同 | 可能被替换成限制页 | 抓当前页面文本看看 |
| 消息发送失败 / 提示「发送失败」 | 被限制 | 停止，第二天再试 |

### 脚本里应该怎么做

**每个关键动作之后都要验证业务结果**，而不是验证「函数没报错」：

```js
// ❌ 只验证点击
const r = await pe(`... el.click(); return 'clicked'; `);
if (r === 'clicked') console.log('✅ 成功');   // ← 自欺欺人

// ✅ 验证业务状态真的变了
//    例：BOSS 看输入框是否清空；智联/猎聘看弹窗是否消失 + 页面是否出现成功提示
const stillOpen = await pe(`(function(){
  return document.querySelector('.ant-c-modal-footer') ? 'open' : 'closed';
})()`);
if (stillOpen === 'open') { /* 没投出去 —— 应该停下来诊断，而不是跑下一个 */ }
```

**并且：连续 N 次动作失败就应该中止整个批次。**

```js
let consecutiveFail = 0;
...
if (!ok) {
  consecutiveFail++;
  if (consecutiveFail >= 3) {
    console.log('⚠️ 连续 3 次未生效，中止本批次（可能是被限制或页面结构变了）');
    break;
  }
} else { consecutiveFail = 0; }
```

## 4. 通用原则

### 4.1 点击后必须验证业务结果
见上一节。这是踩过最多的一类坑。

### 4.2 失败要停，不要继续
失败继续跑 = 制造「只浏览不投递」的异常特征。连续失败即中止。

### 4.3 页面加载次数本身就是风控信号
投递类脚本是「1 次列表 + N 次详情页」。
如果每个岗位要打开 2 次页面（列表 + 详情），节奏就要比「列表内直接投递」更慢。

### 4.4 节奏
- 每个动作之间 **2–5 秒** 随机（不要用固定值，固定间隔本身就是机器特征）
- 每个岗位之间 **8–20 秒** 随机
- 批次之间 **15–25 秒**
- 白天操作，晚上停

### 4.5 不要绕过验证码
遇到验证码一律停手交给用户。这是刻意保留的边界 ——
绕过它既有技术风险也有账号风险，而且违反平台条款。

| 平台 | 单次批量 | 岗位间隔 | 单日上限 | 备注 |
|---|---|---|---|---|
| BOSS直聘 | 20–30 | 12–27 秒 | 30–50 | 有主动反自动化，留足余量 |
| 智联招聘 | 10–20 | 8–18 秒 | 30–50 | 一键投递，简历一起发 |
| 前程无忧 | 10–20 | 7–16 秒 | 30–50 | 同上 |
| 猎聘 | **3–5** | **15–25 秒** | **10** | 每个岗位要跳详情页，最易触发 |

## 6. 触发之后怎么恢复

1. **立刻停止该平台的一切操作**（包括只读的页面浏览）
2. 按提示完成验证（短信验证码 / 滑块）—— **必须用户本人做**
3. 确认恢复：重新打开首页，检查是否还有异常提示、登录态是否正常
4. **先小批量验证**（3 个左右），确认每次动作都真正生效
5. 间隔至少一天再恢复常规节奏。**不要当天就放量**

> 猎聘事件实测：完成短信验证后，当天小批量投 3 个是安全的；
> 但更稳妥的做法是第二天再恢复。

## 7. 一句话清单

- ✅ 每个动作后验证**业务结果**
- ✅ 连续失败 3 次 → **中止批次**
- ✅ 看到「账号行为异常 / 验证码 / 要求重新登录」→ **立刻停，交用户**
- ✅ 失败时先查「动作生效了没」，再怀疑「是不是太快」
- ❌ 不要用「点击成功」当成功判据
- ❌ 不要在失败后继续跑下一个
- ❌ 不要绕过验证码
- ❌ 不要在夜里高频跑
